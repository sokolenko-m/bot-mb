# Отчёт по загрузке конструкторов — Telegram Mini App

Telegram-приложение: выбираете конструктора и период — получаете список задач
с план/факт часами и итог, с экспортом в Excel или PDF (файл присылает бот
прямо в чат). Данные берутся из той же базы Notion "Задачи", что использует
[notion_scheduler](../notion_scheduler) (локальный планировщик графика).

Доступ — только у людей, отмеченных в Notion: база «Участники_1», заполнено
поле «Telegram ID» и стоит галочка «Доступ до звітів» (список обновляется
раз в 5 минут). Дополнительно всегда пускает ID из `ALLOWED_USER_IDS`
(запасной доступ администратора, работает даже если Notion недоступен).
Кто пользователь — проверяется подписью, которую Telegram сам прикладывает
к каждому открытию приложения (подделать нельзя, не зная токен бота).

## 1. Бот в Telegram

Токен бота уже есть. Если нужно создать заново — напишите @BotFather:
```
/newbot
```
и следуйте подсказкам. Токен придёт в ответ, вида `123456:ABC-DEF...`.

**Важно:** держите токен в секрете — он даёт полный контроль над ботом. Если
токен когда-либо "засветился" не в защищённом месте — перевыпустите его:
@BotFather → `/mybots` → выбрать бота → Bot Settings → API Token → Revoke.

## 2. Ваш Telegram ID и ID руководителей отделов

Каждому, кому нужен доступ, написать боту `@userinfobot` — он в ответ пришлёт
числовой `Id`. Его вписать в «Участники_1» → «Telegram ID» и поставить
галочку «Доступ до звітів». Если человек откроет приложение без доступа,
оно само покажет его Telegram ID.

## 3. Публикация кода на GitHub

Render разворачивает сервис из git-репозитория. В папке `telegram_report`:

```bash
git init
git add .
git commit -m "Initial commit"
```

Создайте пустой репозиторий на https://github.com/new (можно приватный),
затем:

```bash
git remote add origin https://github.com/<ваш-логин>/<репозиторий>.git
git branch -M main
git push -u origin main
```

`.env` в репозиторий не попадёт — он в `.gitignore`. Секреты задаются на
Render отдельно (шаг ниже), в коде их нет.

## 4. Деплой на Render

1. https://dashboard.render.com → **New** → **Web Service**.
2. Подключите GitHub-репозиторий из шага 3.
3. Настройки:
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
4. Вкладка **Environment** → добавьте переменные (значения — из `.env.example`,
   реальные секреты никому не передавайте кроме как через эту форму):
   - `NOTION_TOKEN`
   - `NOTION_DATA_SOURCE_ID`
   - `TELEGRAM_BOT_TOKEN`
   - `ALLOWED_USER_IDS`
5. **Create Web Service** — через пару минут появится адрес вида
   `https://<имя>.onrender.com`.

На бесплатном плане сервис "засыпает" после 15 минут без запросов и
просыпается ~30 секунд при следующем открытии — для отчётов, которые
открывают не каждую минуту, это обычно не мешает.

## 5. Подключить Web App к кнопке бота

@BotFather → `/mybots` → выбрать бота → **Bot Settings** → **Menu Button** →
**Configure Menu Button** → отправить URL с Render (`https://<имя>.onrender.com`)
→ затем отправить текст кнопки, например `Отчёты`.

Готово — в чате с ботом внизу появится кнопка, открывающая приложение.

## 6. Добавить / убрать людей с доступом

Notion → «Участники_1» → у человека заполнить «Telegram ID» и поставить
(или снять) галочку «Доступ до звітів». Через 5 минут изменение вступит в силу,
Render трогать не нужно.

`ALLOWED_USER_IDS` на Render — только для запасного доступа администратора.

## Локальный запуск (для проверки/разработки)

```bash
npm install
cp .env.example .env   # заполнить реальными значениями
npm start
```

Открыть Mini App вне Telegram напрямую нельзя (нужна подпись initData от
Telegram) — тестировать удобнее прямо через бота после деплоя, либо
подставлять свою тестовую initData вручную при отладке.

## Структура проекта

- `server.js` — Express-сервер, маршруты API.
- `notion.js` — запросы к Notion (список конструкторов, задачи за период).
- `report.js` — агрегация (суммы план/факт часов, нові задачі, відсутність, статус планувальника).
- `dates.js` — форматування дат за київським часом.
- `export_xlsx.js` / `export_pdf.js` — генерация файлов отчёта.
- `telegram_auth.js` — проверка подписи Telegram и доступа (Notion «Доступ до звітів» + `ALLOWED_USER_IDS`).
- `telegram_bot.js` — отправка готового файла пользователю через бота.
- `public/index.html` — сама страница приложения (выбор, таблица, кнопки).
